# Вебзастосунок обліку та видачі книг бібліотеки коледжу

Курсовий проєкт з дисципліни «Конструювання програмного забезпечення».

- **Тема:** 15. Бібліотека коледжу
- **Автор:** Турчак Богдан Богданович, група ІС-23-01
- **Рівень складності:** ІІІ — Достатній (7–9 балів)
- **Версія:** 0.3.0

## Призначення

Читач на сторінці `client.html` переглядає каталог, подає заявку на книгу й стежить
за її статусом. Бібліотекар на сторінці `admin.html` розглядає заявки, видає й
приймає книги, веде каталог і читачів. Обидві сторінки працюють з одним JSON Server.
Постановка завдання — [docs/task.md](docs/task.md).

## Сторінки та API

| Що | Адреса | Для кого |
|---|---|---|
| Стартова сторінка | http://127.0.0.1:5500/index.html | вибір ролі |
| Сторінка читача | http://127.0.0.1:5500/client.html | читач |
| Сторінка бібліотекаря | http://127.0.0.1:5500/admin.html | бібліотекар |
| API: книги | http://localhost:5000/books | обидві сторінки |
| API: читачі | http://localhost:5000/readers | обидві сторінки |
| API: заявки | http://localhost:5000/requests | обидві сторінки |

Адреса API задана в одному місці — `js/config.js` (`API_URL`).

## Запуск

Потрібно: [Node.js](https://nodejs.org/) LTS (разом із npm), VS Code з розширенням
**Live Server** (Ritwick Dey). Посилання на `localhost` працюють лише на комп'ютері,
де запущено сервер.

1. Відкрити папку `course-project` у VS Code (**File → Open Folder**).
2. Встановити залежності — JSON Server **0.17.4** (версія зафіксована в `package.json`
   і `package-lock.json`):
   ```
   npm install
   ```
3. Запустити JSON Server і не закривати термінал:
   ```
   npm run server
   ```
   Це те саме, що `npx json-server --watch db.json --port 5000`.
   Перевірка: http://localhost:5000/books повертає масив книг.
4. Відкрити `index.html` → правий клік → **Open with Live Server**.

Повернути початкові демонстраційні дані: зупинити сервер (`Ctrl+C`) і виконати
`git checkout -- db.json`.

Сторінки використовують ES-модулі (`<script type="module">`), тому відкривати їх
треба через HTTP (Live Server), а не подвійним кліком по файлу.

## Функції

Етап 3 — готовий інтерфейс обох сторінок і читання даних через API.

| Функція | Стан |
|---|---|
| Каталог книг, пошук, фільтр, сортування (GET `/books`) — обидві сторінки | готово |
| Статус заявок читача за квитком (GET `/readers?ticket=`, `/requests?readerId=`) | готово |
| Перелік заявок, книг і читачів у бібліотекаря (GET) | готово |
| Стани: завантаження, немає даних, успіх, помилка; повідомлення валідації; діалог підтвердження | готово |
| Створення заявки (POST), зміна статусу (PATCH), керування книгами й читачами (POST, PATCH, DELETE) | етап 4 |
| Патерн State для переходів статусів | етап 4 (спроєктовано) |

## Патерни

| Патерн | Файл | Призначення |

## Структура проєкту

```
course-project/
├── index.html            — стартова сторінка (вибір ролі)
├── client.html           — сторінка читача
├── admin.html            — сторінка бібліотекаря
├── css/style.css         — спільні стилі
├── js/
│   ├── config.js         — адреса API та константи
│   ├── http.js           — fetch + перевірка response.ok
│   ├── errors.js         — типи помилок
│   ├── repository.js     — патерн Repository
│   ├── request-state.js  — статуси заявки (патерн State)
│   ├── validation.js     — перевірка введених даних
│   ├── ui.js             — спільні функції інтерфейсу
│   ├── utils.js          — дати, екранування HTML
│   ├── client.js         — логіка сторінки читача
│   └── admin.js          — логіка сторінки бібліотекаря
├── db.json               — дані: books, readers, requests
├── package.json, package-lock.json — залежності (json-server 0.17.4)
└── docs/                 — постановка, патерни, UML, скриншоти
```
