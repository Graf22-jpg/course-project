## 2. Призначення програми

Програма з'єднує читачів і бібліотекаря коледжу через спільні дані в JSON Server.
Читач на сторінці `client.html` переглядає каталог, подає заявку на книгу і стежить
за її статусом. Бібліотекар на сторінці `admin.html` розглядає заявки, видає й
приймає книги, веде каталог і список читачів.

**Проблема, яку розв'язує програма:** під час паперового обліку важко швидко
перевірити, чи є вільний примірник, а читач не знає, чи відкладено для нього книгу.
Програма резервує примірник під час схвалення заявки, не дає схвалити заявку без
вільних примірників і показує читачу актуальний статус.

## 3. Користувачі

| Роль | Сторінка | Що робить |
|---|---|---|
| Читач (студент, викладач) | `client.html` | Переглядає каталог, подає заявку, переглядає статус своїх заявок |
| Бібліотекар | `admin.html` | Змінює статуси заявок, керує книгами й читачами |

Реєстрація, вхід і ролі до обов'язкового обсягу не входять. Читач ідентифікується
номером читацького квитка. Поділ на дві сторінки не є захистом доступу на сервері.

## 4. Дані (`db.json`)

### 4.1 `books` — книги (пропозиції)

| Поле | Тип | Обмеження |
|---|---|---|
| `id` | рядок | Порядковий номер "1", "2", … |
| `title` | рядок | 2–150 символів |
| `author` | рядок | 2–100 символів |
| `category` | рядок | Зі списку розділів (`js/config.js`) |
| `year` | число | Ціле, 1900 … поточний рік |
| `quantity` | число | Ціле, ≥ 0, не менше зарезервованих і виданих |
| `available` | число | Ціле, 0 … `quantity` |

### 4.2 `readers` — читачі

| Поле | Тип | Обмеження |
|---|---|---|
| `id` | рядок | Порядковий номер |
| `fullName` | рядок | 3–100 символів, лише літери, пробіл, апостроф, дефіс |
| `group` | рядок | Група або посада, ≥ 2 символи |
| `ticket` | рядок | Унікальний, формат `Ч-001` |

### 4.3 `requests` — заявки

| Поле | Тип | Опис |
|---|---|---|
| `id` | рядок | Номер заявки |
| `bookId`, `readerId` | рядок | Посилання на книгу й читача |
| `comment` | рядок | Коментар читача, ≤ 200 символів |
| `status` | рядок | `new`, `approved`, `issued`, `returned`, `rejected` |
| `createdAt` | дата | Дата подання |
| `decisionDate` | дата / null | Дата схвалення або відхилення |
| `issueDate`, `dueDate` | дата / null | Дата видачі; строк повернення = видача + 14 днів |
| `returnDate` | дата / null | Дата повернення |
| `rejectReason` | рядок / null | Причина відхилення |

«Прострочена» — це видана заявка, у якої `dueDate` минула; окремо не зберігається.

## 5. Статуси заявки та допустимі переходи

| Із | У | Хто | Умова / наслідок |
|---|---|---|---|
| — | Нова | Читач | Створення заявки (POST) |
| Нова | Схвалена | Бібліотекар | Лише якщо `available > 0`; `available − 1` (примірник відкладено) |
| Нова | Відхилена | Бібліотекар | Причина необов'язкова |
| Схвалена | Видана | Бібліотекар | `issueDate` = сьогодні, `dueDate` = +14 днів |
| Схвалена | Відхилена | Бібліотекар | `available + 1` (резерв знято) |
| Видана | Повернена | Бібліотекар | `returnDate` = сьогодні, `available + 1` |
| Повернена, Відхилена | — | — | Кінцеві стани, переходів немає |

Будь-який інший перехід заборонено (патерн State, `js/request-state.js`).

## 6. Функціональні вимоги

### 6.1 Сторінка читача (`client.html`)

| Код | Вимога |
|---|---|
| ФВ-01 | Перегляд каталогу книг із кількістю вільних примірників (GET `/books`) |
| ФВ-02 | Пошук за назвою або автором, фільтр за розділом і «лише в наявності», сортування за назвою, автором, роком |
| ФВ-03 | Подання заявки (POST `/requests`) з перевірками: обрано книгу; квиток у форматі `Ч-001`; читач існує; книга є в наявності; немає незавершеної заявки на цю книгу; не більше 3 незавершених заявок |
| ФВ-04 | Перегляд статусу своїх заявок за номером квитка (GET `/requests?readerId=…`) і кнопка «Оновити» |

### 6.2 Сторінка бібліотекаря (`admin.html`)

| Код | Вимога |
|---|---|
| ФВ-05 | Перегляд заявок, пошук за книгою або читачем, фільтр за статусом, зокрема «прострочені» |
| ФВ-06 | Зміна статусу заявки (PATCH `/requests/:id`) лише за допустимими переходами (розділ 5) |
| ФВ-07 | Відхилення заявки з необов'язковою причиною, яку бачить читач |
| ФВ-08 | Керування книгами: перегляд, додавання, редагування, видалення (GET, POST, PATCH, DELETE `/books`) |
| ФВ-09 | Керування читачами (GET, POST, PATCH, DELETE `/readers`) |
| ФВ-10 | Правило пов'язаних заявок: книгу або читача з незавершеними заявками видаляти не можна; завершені заявки залишаються в історії з позначкою «вилучено» |
| ФВ-11 | Підтвердження видалення й відхилення в діалоговому вікні |

### 6.3 Спільні вимоги

| Код | Вимога |
|---|---|
| ФВ-12 | Перевірка введення з повідомленням біля поля; дані з помилками не надсилаються |
| ФВ-13 | Усі зміни виконуються HTTP-запитами й зберігаються в `db.json`; після перезавантаження та перезапуску сервера дані на місці |

## 7. Нефункціональні вимоги

| Код | Вимога |
|---|---|
| НФВ-01 | Інтерфейс українською; Chrome, Edge, Firefox; спільні стилі `css/style.css` |
| НФВ-02 | Сторінки без горизонтального прокручування на екранах від 360 px (таблиці перетворюються на картки) |
| НФВ-03 | Стани завантаження, відсутності даних, успіху та помилки видно користувачу |
| НФВ-04 | Адреса API зберігається в одному місці — `js/config.js`; кожна відповідь перевіряється (`response.ok`) |
| НФВ-05 | Недоступність JSON Server і відсутній запис (404) показуються зрозумілим повідомленням; після помилки немає повідомлення про успіх |
| НФВ-06 | Дані не зберігаються в `localStorage` чи масивах замість JSON Server |

## 8. Головне правило роботи

> **Заявку можна схвалити лише тоді, коли є вільний примірник (`available > 0`).
> Значення `available` завжди ціле від 0 до `quantity`.**

## 10. Що не входить до проєкту

Реєстрація й авторизація, серверний захист доступу, автоматичне оновлення сторінок
(достатньо кнопки «Оновити»), штрафи, звіти й експорт (високий рівень).
